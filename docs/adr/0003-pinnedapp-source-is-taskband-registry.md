# PinnedApp の取得元はタスクバーのレジストリ値とし、固定フォルダは予備にする

ADR-0001 ではタスクバー固定フォルダのショートカットを唯一の取得元とした。運用してみると、パッケージ型（MSIX / ストア）のアプリを固定してもこのフォルダにはショートカットが作られず、Launcher に出てこないことが分かった。タスクバー自身は固定一覧をレジストリ値（Explorer\Taskband の Favorites）に PIDL の列として持っており、PIDL の中身は公開 API（SHGetNameFromIDList）で解析名と表示名に解決できる。値の区切り方（1 バイトのヘッダー、4 バイトのサイズ、PIDL の繰り返し）だけはこちらで解釈するが、PIDL の内部構造には触れない。この値を主な取得元にし、従来型もパッケージ型もタスクバーの表示順で得る。フォルダは、レジストリが読めない場合の予備と、解決漏れの補完に使う。

独自のアプリ登録機能を持たないという ADR-0001 の方針は変えない。

## Consequences

- タスクバーの並び順が取れるようになったので、Launcher の既定の並びは「タスクバーと同じ順」にする。ドラッグによる独自の並べ替えは設定で選んだ場合だけ有効にし、その保存形式は従来どおり。
- 値の区切り形式は非公開である。区切りが解釈できなくなった場合は、そこまでに読めた分に加えてフォルダのショートカットで補うので、従来型アプリが消えることはない。パッケージ型だけが欠ける退避になる。
- PinnedApp の Id は、従来型ならショートカットのファイル名、パッケージ型なら AppUserModelId。保存済みの独自並び順はそのまま使える。
